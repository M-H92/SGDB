Introduction

Dans ce chapitre, nous allons tenter de mettre en place des requêtes aggrégeant des données qui, bien qu'ayant un sens métier, n'ont pas forcément les liens requis en base de données pour une récupération simple.
Pour nous aider, nous allons explorer le concept d'union.

Problème de récupération

Si vous n'avez pas de chats vaccinés dans vos données, utilisez cette requête pour mettre à jour vos données : 


      INSERT INTO cat_vaccin
      (innoculation, cat, vaccin_name)
      VALUES 
      ('01-01-2026', 'Monza', 'rage'),
      ('01-01-2026', 'Monza', 'grippe'),
      ('01-01-2025', 'Monza', 'rage'),
      ('01-01-2025', 'Monza', 'grippe'),
      ('01-01-2025', 'Plume', 'rage'),
      ('01-01-2025', 'Plume', 'grippe');

Dans les chapitres précédents, nous avons mis en place une table de vaccin liée, via une table de liaison, à notre table de chats.
Ceci nous permet de récupérer les chats vaccinnés avec éventuellement des jointures selon les informations souhaitées.
Pour récupérer les chats vaccinés, nous pouvions utiliser ce genre de requête : 

-- uniquement avec la table cat_vaccin
SELECT * FROM cat_vaccin
WHERE cat LIKE 'Monza';

-- en ajoutant la table de vaccin
SELECT cv.cat, v.name, cv.innoculation FROM cat_vaccin AS cv
LEFT JOIN vaccin AS v ON cv.vaccin_name = v.name
WHERE cv.innoculation + v.periodicity >= now()

le première requête nous permet d'identifier les vaccins innoculés à un chat en particulier.
La deuxième nous permet de voir tout les vaccins en ordre avec la récupération de la périodicité de vaccination dans la table de vaccin.
Mais un problème survient si je souhaite récupérer l'état de vaccination complet de chaque chat
Si je souhaite récupérer les vaccins qui ne sont "plus" en ordre, je peux simplement renverser le signe de ma condition 

SELECT cv.cat, v.name, cv.innoculation FROM cat_vaccin AS cv
LEFT JOIN vaccin AS v ON cv.vaccin_name = v.name
WHERE cv.innoculation + v.periodicity < now()

Si je souhaite récupérer les chats pour lesquels je n'ai pas réalisé un vaccin, je peux utiliser un simple left join 

SELECT c.cat, cv.vaccin_name FROM cat as c
LEFT JOIN cat_vaccin AS cv ON cv.cat = c.cat;

Je peux aussi, si je souhaite, récupérer les vaccins pour lesquels je n'ai pas réalisé de vaccin, je peux réaliser la même opération de puis la table de vaccins.
Mais notez qu'avec cette requête, je n'ai qu'une seule fois le nom de 'Charlie' qui apparait.
Idéalement, j'aimerais disposer de son nom ainsi que du nom des vaccins manquant.
Pour se faire, il faudrait d'abord récupérer la liste complète des vaccins et joindre ce résultat de telle manière à mettre en correspondance les informations des trois tables. Ce qui devient plus complexe. Une autre solution serait d'utiliser la notion d'Union

Union

Le mot clé UNION ainsi que ses variantes EXCEPT et INTERSECT permettent d'ajouter ou de retirer les éléments d'un dataset sur base d'un autre dataset.
En pratique, il permet d'ajouter les lignes de réponse d'une requête aux lignes de réponse d'une autre requête ou de retirer les lignes de réponse d'une requête aux lignes de réponse d'une autre requête.
Par exemple, retirer la liste des vaccins réalisés qui est une requête simple (voir plus haut) de la liste de tout vaccins possibles pour un ou des chats, récupérable facilement avec la requête suivante : 

SELECT c.cat, v.name FROM cat AS c
CROSS JOIN vaccin AS v;

Ainsi, nous obtenons la requête suivante : 

-- récupération de tout les vaccins possibles
SELECT c.cat, v.name FROM cat AS c
CROSS JOIN vaccin AS v
-- sauf ceux qui sont effectifs
EXCEPT
SELECT cat, vaccin_name FROM cat_vaccin;

Essayez cette requête en remplaçant le mot-clé EXCEPT par le mot-clé UNION ou INTERSECT et analysez les différences

Type d'union

Nous avons présenté ici trois type d'unions différents : UNION - EXCEPT et INTERSECT
De la même manière que les jointures disposaient de diffénts types (FULL - OUTER - INNER), les trois types d'union récupèrent des données différents basées sur une comparaison de chaque colonne des différents sets de données.
Ainsi, EXCEPT ne récupère que les éléments qui sont différents dans les deux sets.
INTERSECT ne récupère que les élements qui sont identiques dans les deux sets (sans doublons)
Union récupère tout.
Pour ce dernier, une variante est disponible avec un UNION ALL. Cette dernière laisse les doubles dans les résultats

Limitations

Ce mot-clé, intéressant, dispose de quelques limites. Essayons par exemple de récupérer en plus les vaccins déjà réalisés et, pour ceux-ci, la date d'innoculation. 

-- Récupération de la dernière innoculation
SELECT cat, vaccin_name, MAX(innoculation) FROM cat_vaccin
GROUP BY (cat, vaccin_name);

-- Récupération des vaccins qui devraient être réalisés
SELECT c.cat, v.name FROM cat AS c
CROSS JOIN vaccin AS v
EXCEPT
SELECT cat, vaccin_name FROM cat_vaccin;

-- Tentative de mettre les deux ensemble avec un Union
SELECT c.cat, v.name, null FROM cat AS c
CROSS JOIN vaccin AS v
EXCEPT
SELECT cat, vaccin_name, null FROM cat_vaccin
UNION
SELECT cat, vaccin_name, MAX(innoculation) FROM cat_vaccin
GROUP BY (cat, vaccin_name);

Impossible d'utiliser l'union dans ce cas-ci.
Heureusement, le message d'erreur est on ne peut plus clair : chaque requête UNION doit avoir le même nombre de colonnes
Essayons ceci : 

-- Ajout d'une colonne "en dur" 
-- pour respecter les limitations des unions
SELECT c.cat, v.name, null::date FROM cat AS c
CROSS JOIN vaccin AS v
EXCEPT
SELECT cat, vaccin_name, null::date FROM cat_vaccin
UNION
SELECT cat, vaccin_name, MAX(innoculation) AS innoculation FROM cat_vaccin
GROUP BY (cat, vaccin_name)
ORDER BY cat;

En utilisant une "fausse" colonne (en ajoutant une donnée "brute" dans le résultat de nos premières requêtes), nous avons pu passer outre cette limitation.

Attention lors de l'utilisation de ce mot-clé de bien penser que chaque requête est réalisée complètement avant d'appliquer les unions, excepts, ou intersect.
Bien que le nombre de ligne résultant puisse être faible après un except, il faut garder en tête que chaque action a été pleinement réalisée à priori avec l'impact associé sur les performances de la requête

Conclusion

Dans ce chapitre, nous avons exploré le concept d'union.
Ce concept nous permet d'aggréger un set de données avec un autre.
Une fois réalisé, cet aggrégat permet d'ajouter ou de retirer des lignes de résultat au résultat final selon le mot clé utilisé.
